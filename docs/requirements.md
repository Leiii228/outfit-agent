P4-2 讓 Claude Code 寫架構文件

我不是寫程式的人，請用我看得懂的中文寫架構文件，專有名詞第一次出現時用一句話解釋。



文件要包含這些段落：

1\. 專案說明與目標

2\. 整體架構圖（用 mermaid 畫，看得出「上傳者 → Discord 頻道 → 我電腦上的 agent → claude -p → 本機 DATA\_DIR」之間的關係，也要畫出「!指令」和「每週提醒」的路線）

3\. 技術選擇：用哪個 Discord 套件、怎麼用 Gateway 模式、claude -p 怎麼呼叫、長條圖用什麼畫、每週提醒怎麼排程，每一項寫「選了什麼」和「為什麼」

4\. 一張照片的資料流：有人上傳 → 排隊 → claude -p 分析 → 檢查結果 → 對照這個人以前的紀錄 → 建檔存照片 → 回覆，各自發生什麼事

5\. claude -p 的約定：

&nbsp;  - 要它回「固定格式的 JSON」，欄位至少有：是不是穿搭照片、單品清單（每件有類型、顏色、簡短描述）、風格描述

&nbsp;  - 類型和顏色要從固定的選項裡挑（請你列出選項），這樣之後才能比對「同一件」和統計顏色

&nbsp;  - agent 怎麼解析這個 JSON；如果它回的不是合法 JSON、或欄位缺少、或類型顏色不在選項裡，agent 要怎麼處理（不可以直接當掉）

6\. 不是穿搭照片時怎麼處理：一樣建檔、一樣存照片、一樣回覆，單品清單欄寫「不是穿搭」，風格描述欄寫判定出來的東西，而且不算進個人統計

7\. 多人同時上傳：怎麼排隊、處理前先加 ⏳ 提示

8\. 紀錄：Excel 要有哪些欄位、怎麼「一直往下加」而不是每次覆蓋

9\. 分人處理：為什麼用 Discord user id 而不是暱稱；每個人的統計怎麼從 Excel 算出來

10\. 個人統計怎麼算：穿搭總數、最常穿的顏色前三名、「這件第 N 次穿、上次是幾天前」怎麼判斷（類型＋顏色相同就算同一件）

11\. 指令：!紀錄、!統計、!冷宮 各自讀哪些資料、怎麼算、回覆長什麼樣子；!統計 的長條圖怎麼產生、怎麼傳回 Discord、暫存圖檔放哪裡

12\. 每週提醒：每週一早上 9 點（以我電腦的本地時間為準）發什麼內容；agent 沒開著時錯過了怎麼辦

13\. 照片存放：資料夾在哪、檔名規則（日期時間 + 風格簡稱）、檔名裡不能有哪些字、同一秒撞名怎麼辦

14\. 回覆內容：回覆上傳者時要包含哪些欄位（單品、風格、以前穿過的單品、穿搭總數、顏色前三名）

15\. 設定：.env 有哪些項目（DISCORD\_TOKEN、CHANNEL\_ID、CLAUDE\_MODEL、DATA\_DIR），哪一個絕對不能公開、不能 commit

16\. 安全（這一節很重要）：

&nbsp;   「照片」、「上傳者打的字」、「指令後面接的文字」都是別人送進來的內容。請列出：別人可以用這些內容做出哪些壞事，agent 各自要怎麼擋。至少涵蓋這四類，並且在架構文件裡把每一類當成一段「防護」寫清楚：

&nbsp;   - 防護 1：claude -p 只在「只放這一張照片」的暫存資料夾裡執行，讀不到 DATA\_DIR 裡別人的照片和紀錄；claude -p 能用的工具和權限也要限制

&nbsp;   - 防護 2：上傳者打的字只能當「資料」，不能被當成給 claude -p 的指令

&nbsp;   - 防護 3：claude -p 回來的結果要檢查；風格簡稱拿去當檔名前，要清掉會造成路徑亂跑的字（/、\\、..、冒號等）

&nbsp;   - 防護 4：寫進 Excel 的文字若以 =、+、-、@ 開頭，要處理成純文字，避免打開 Excel 時被當公式

&nbsp;   請在文件裡說明：程式裡這四段防護會各自用清楚的註解標起來（開始 / 結束）。

17\. 額度：每處理一張照片都會用掉我自己的 Claude 額度，頻道裡的人可以一直傳。請說明這件事的風險，以及 CHANNEL\_ID 只聽一個頻道的意義。

18\. 這一版刻意不做的事（例如：不精準辨識是不是同一件衣服、不做長時間雲端服務），以及為什麼

19\. repo 的資料夾結構

20\. 驗證清單：自己測試時要測哪些項目才算完成（每個功能、分人、不是穿搭、Excel 開著時、連續傳多張）

P6 做出 agent

請依照 docs/architecture.md 把這個 agent 寫出來。先說明你打算怎麼做、會裝哪些套件，等我說「開始」再動手。



需求重點：

1\. 用 Python 3.12 + uv 管理環境與相依套件

2\. Discord 用 Gateway（bot）模式；只聽 .env 裡 CHANNEL\_ID 指定的那一個頻道

3\. 收到有圖片附件的訊息時：

&nbsp;  - 先對那則訊息加上 ⏳ 反應，表示收到、排隊中

&nbsp;  - 多張同時進來要一張一張排隊處理，不要同時開很多個 claude -p

4\. 用 claude -p 分析照片，要求它回「固定格式 JSON」：是不是穿搭照片、單品清單（每件有類型、顏色、簡短描述）、風格描述。類型和顏色要從架構文件列的固定選項裡挑。

&nbsp;  agent 要先解析並檢查這個 JSON：不是合法 JSON、欄位缺少、或類型顏色不在選項裡時，要回覆上傳者「分析失敗，請再傳一次」，不可以讓程式當掉。

5\. 記錄：

&nbsp;  - 存成一個可以持續往下加的 Excel 檔（新的一列加在最後，不要覆蓋）

&nbsp;  - 欄位：日期時間、上傳者名稱、上傳者 user id、單品清單、主要顏色、風格描述、這個人的穿搭總數、照片存放位置

&nbsp;  - Excel 若正在被我打開而寫入失敗，要在終端機印出警告並重試，不可以讓程式當掉

6\. 分人處理：所有統計都用 Discord user id 分開算，不用暱稱

7\. 對照之前的紀錄：這次的單品若「類型＋顏色」和這個人以前的紀錄相同，回覆「這件你第 N 次穿，上次是 M 天前」

8\. 照片存放：

&nbsp;  - 存進 DATA\_DIR 底下一個固定的照片資料夾

&nbsp;  - 檔名用「YYYY-MM-DD hh-mm-ss 風格簡稱.jpg」（用 - 不用冒號，Windows 才存得了）

&nbsp;  - 同一秒撞名時在後面加 -2、-3

9\. 不是穿搭照片時：一樣建檔、一樣存照片、一樣回覆；單品清單欄寫「不是穿搭」，風格描述欄寫判定出來的東西（例如「一隻貓」），而且不算進個人統計

10\. 回覆上傳者：用「回覆該則訊息」的方式回在頻道裡（不要用私訊），內容包含：是不是穿搭、單品清單、風格描述、哪幾件以前穿過、這個人的穿搭總數、最常穿的顏色前三名

11\. 指令（只回覆打指令的那個人自己的資料）：

&nbsp;   - !紀錄：最近 5 筆穿搭紀錄（日期、單品）

&nbsp;   - !統計：一張顏色分布長條圖（圖片附件）加上各類型單品件數；圖檔畫完傳出去後刪掉

&nbsp;   - !冷宮：超過 14 天沒穿到的單品

&nbsp;   - 沒有紀錄的人打指令時，回覆「你還沒有紀錄」，不可以當掉

12\. 每週提醒：每週一早上 9 點（我電腦的本地時間），在頻道發一則訊息，列出每個人上週記錄了幾套、最常穿的顏色；上週沒人記錄就不發

13\. 設定全部從 .env 讀：DISCORD\_TOKEN、CHANNEL\_ID、CLAUDE\_MODEL、DATA\_DIR

14\. 為了測試，請讓每週提醒可以手動觸發一次（例如我打 !測試提醒），測完我會請你拿掉或保留



安全（請務必照做）：

把下面四類防護，在程式裡「各自包成一段」，用這種註解把每一段的開始和結束標清楚：



&nbsp;   # ==== 防護 1：claude -p 的檔案範圍隔離　開始 ====

&nbsp;   ...這一段的程式...

&nbsp;   # ==== 防護 1 結束 ====



四段分別是：

\- 防護 1：呼叫 claude -p 時，工作資料夾設成「只有這一張待分析照片」的暫存資料夾，不能讓它讀到 DATA\_DIR 裡別人的照片和紀錄；並限制 claude -p 能用的工具，只給讀那張照片需要的

\- 防護 2：上傳者打的字只能當「要分析的資料」，絕對不能把它接進給 claude -p 的指令裡

\- 防護 3：檢查 claude -p 回來的結果；風格簡稱拿去當檔名前，先清掉 / \\ .. 冒號等會讓路徑亂跑的字

\- 防護 4：寫進 Excel 的文字若以 = + - @ 開頭，先處理成純文字



四段防護全部開著。請在 README 或程式開頭用註解列出這四段各在第幾行附近。



另外請在 README 加一節「功能」，條列這個 agent 做了哪些事（對應 docs/requirements.md 的功能一節）。



最後：請提供用 uv 啟動 agent 的指令，並確認 .env 和 DATA\_DIR 都在 .gitignore 裡。
